Exchange Online Protection Baseline

A guided path from approved inputs to a reviewed Exchange change

Start the eight-step wizard
Example only: This repository is not an official Microsoft product or service. It does not provision a tenant, establish licensing, grant access, or certify production readiness. Every deployment requires independently approved inputs, current entitlement evidence, least-privilege access, and change authorization.

Supported scope

The active workflow evaluates a versioned Exchange-only profile for a Worldwide tenant. It uses Microsoft-managed Standard and Strict preset security policies without copying or modifying their individual settings.

  • Standard preset for the approved broad recipient population
  • Strict preset for an approved priority-user group
  • Exchange Online hardening and evidence collection
  • Fail-closed input, entitlement, approval, and evidence contracts

Protection profiles

Standard

Microsoft's recommended baseline profile for broad recipient coverage.

Strict

A more aggressive Microsoft-managed profile for selected high-value targets or priority users.

Automated Investigation and Response, Threat Explorer, and Attack Simulation Training are separate Microsoft Defender for Office 365 Plan 2 capabilities. Assigning Strict does not enable them.

What this repository does not claim

  • It does not reproduce Microsoft-managed preset values in local templates.
  • It does not provide a generic detect-only mode for Standard or Strict presets.
  • It does not infer entitlement from a suite name or declare that capabilities have no additional licensing cost.
  • It does not certify DNS, identity, licensing, client, Purview, or other externally owned readiness.
  • It does not validate sovereign-cloud or hybrid deployment paths.

Configuration files

One versioned Exchange-only configuration; Standard and Strict are recipient-targeted Microsoft presets, not separate script downloads.

Start with these files

  • exchange-only.v1.json - retained Exchange control configuration
  • exchange-only.schema.v1.json - closed validation schema
  • exchange-only.manifest.v1.json - retained controls and explicit exclusions
  • parameters.exchange-only.sample.json - example structure only; resolve and protect your own copy

Before you run anything

  • Use approved tenant-specific inputs outside source control; the sample is synthetic and must not be used for a live change.
  • Replace every __ADMIN_REQUIRED:... token with independently approved data.
  • Get current tenant- and recipient-bound entitlement evidence and the required owner approvals.
  • Stop if anything is missing, stale, malformed, or outside the approved scope.

What Standard and Strict mean here

Standard and Strict are Microsoft-managed preset policies. This repository does not ship different scripts for them; administrators initialize the presets in the Microsoft Defender portal and manage the supported recipient scope. Virtually all individual settings in these presets are Microsoft-managed and cannot be customized. Custom policies do not override an applicable Standard or Strict preset because presets have higher precedence.

Runtime and access

  • PowerShell 7.6 or later
  • ExchangeOnlineManagement 3.10.0 or later
  • Worldwide tenant (O365Default)
  • Approved Exchange identity with least-privilege access
  • Protected input and artifact locations outside source control

Use the exact module version approved for the change. Preset policies can be managed through applicable Defender Unified RBAC permissions or Exchange Online Organization Management or Security Administrator role groups. Global Administrator is highly privileged; prefer narrower supported roles.

Recovery

Rollback restores only reviewed settings whose current state still matches the approved change. It cannot undo delivered or processed messages. Follow the approved-change runbook; do not recreate Microsoft-managed preset policies from exported data.

Frequently asked questions

Does preview create a detect-only mail-flow mode?

No. The supported plan and approved preview describe proposed administrative changes. Standard and Strict presets enforce their documented actions when assigned. Microsoft Defender evaluation is a separate feature and is not configured by this workflow.

Can I tune Standard or Strict thresholds?

No. Virtually all individual preset settings are Microsoft-managed. Manage supported recipient scope and exclusions instead. A custom policy does not override an applicable Strict or Standard preset.

Does Strict include AIR?

No. Strict is a Microsoft-managed protection profile. AIR and other advanced investigation capabilities are separate Plan 2 features and require applicable tenant and recipient entitlement.

Are all capabilities included at no extra cost?

No general cost claim can be made. Required licensing depends on the capability and every recipient who benefits from it. Verify current tenant service plans and recipient assignments; do not infer entitlement from a suite display name.

How should false positives be handled?

Submit legitimate messages, URLs, or attachments to Microsoft first. When Microsoft filtering caused the block, the service can create the applicable temporary allow entry. Entity type controls behavior and expiration. Broad or permanent sender allows must not replace authentication fixes, correct scope, or verdict review.

The active configuration prohibits permanent allow entries and requires owner, ticket, timestamps, expiry, and justification for governed entries.

Does this workflow support GCC High or DoD?

No validated support is claimed. The active administrator journey is Worldwide-only. Sovereign and hybrid environments require a separately reviewed and tested journey.
